<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| threshold fixture → release gate | Untrusted threshold JSON crosses into verdict logic |
| aggregated benchmark metrics → release report | Runtime-derived metrics can be incomplete, malformed, or inconsistent with accepted-only semantics |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | T | threshold loader in `ankideck_generator/core/evaluation.py` | mitigate | Validate threshold files with typed models and reject missing comparator/value fields before verdict logic runs. |
| T-05-08 | R | release-readiness report | mitigate | Include experiment fingerprint, generated timestamp, threshold source, and failed-check details so a pass/fail verdict is attributable and reviewable. |
| T-05-09 | D | release gate calculation | mitigate | Compute the gate only from accepted-only benchmark metrics and explicitly fail when required metrics are missing, preventing false passes from partial payloads. |
| T-05-10 | T | accepted-only report adapter in `ankideck_generator/core/evaluation.py` | mitigate | Validate `quality_report.json` payloads with typed models before bundle assembly; reject malformed runtime guardrail or latency sections instead of defaulting silently. |
| T-05-11 | D | benchmark runner / AI budget evidence path | mitigate | Require the runner to read explicit `runtime_guardrails` and `ai_budget_usage` sections from the bundle so runaway-budget conditions stay visible in the verdict path rather than being ignored. |
</threat_model>
